# 22 术语速查与易错说法

> 最终集成（2026-10-20）：当前主线已包括核对、消息、任务/ACL和有界性能实验；“未测”限定于明确环境和范围。ACK可代表持久化重试接管，归档单测数/场景数/计时样本数分开。

| 术语 | 项目中的具体含义 |
| --- | --- |
| ERP | 提供产品/采购/销售/原出入库的基座业务 |
| 履约 | 把销售承诺分配、发出、取消或完成的执行扩展 |
| H/R/A | 实物/预占/可用；A=H−R |
| open/reserved | 未分配/当前已预占 |
| shipped/returned | 累计已发/累计实际退回，分别记录 |
| held/consumed/released | 某次预占剩余/已发消耗/已释放 |
| 快照 | 接管时冻结的商业执行依据 |
| 托管 | 源单已由履约执行，公共ERP写入口需守卫 |
| Port | 同应用受控Java接口，不是网络端口或微服务 |
| 当前读 | 本项目用FOR UPDATE取得最新锁定记录 |
| RC/RR | READ COMMITTED / REPEATABLE READ，具体锁行为取决于查询和约束 |
| 幂等命令 | 同身份同内容重放不再次产生效果并返回原结果 |
| 业务唯一键 | 限制源单绑定、映射等业务身份重复 |
| MANDATORY | 必须已有事务，否则失败 |
| 整事务重试 | 原事务已结束后重新进入完整业务事务 |
| HMAC | 用共享密钥认证原始消息字节 |
| request_hash | 规范化内容指纹，用于判断同键是否改内容 |
| actor0 | Java内部系统到期命令审计身份，不是假管理员 |
| 游标 | 本次扫描的位置，不代表之前每条业务成功 |
| allowance | 可退参考额度，提交还需锁后重算 |
| Outbox/Inbox | 已完成的可靠事件记录/消费者去重，见26 |
| lease/fencing | 已完成消息/任务租约及阻止旧工作者回写的版本机制 |
| 断言 | 对一个预期的检查，不等于一个独立场景 |
| QPS/P95/P99 | 性能指标，M7有本机有界实验，不能外推生产 |

## 常见说法修正

| 易错表达 | 准确表达 |
| --- | --- |
| 我从零写了完整ERP和权限框架 | 基于固定芋道版本二开履约及库存集成 |
| 加事务就不会超卖 | 事务加当前读/锁/条件更新及所有入口共同维护约束 |
| RC没有间隙锁，项目不会死锁 | RC解决历史特定路径，仍有限重试和锁依赖 |
| synchronized能保护两个JVM | 共享MySQL锁与唯一键协调跨进程 |
| 发货先独立释放再独立扣库存 | 同事务降低R，ERP唯一降低H |
| 退货申请一提交就加库存 | 收到货并审核ERP退货后才增加H |
| 退回后shipped减掉 | gross shipped保持，returned单独增加 |
| 到期自动取消 | 释放预占回open，保留订单义务 |
| 合法签名就无需去重 | 认证来源与重复业务分别处理 |
| 有授权表说明仓库权限完成 | M6已接入READ/OPERATE、专用DTO和测试；仍不等于全部ERP |
| 双JVM是分布式微服务 | 同机多个单体实例的共库竞争实验 |
| 60指定单测就是60业务场景/全部上游测试 | 指定测试集合，证据单位不可混用 |
| 重启通过说明任何断电都不丢 | 正常重启与已测故障窗口有边界 |
| Docker文件证明部署通过 | 本机未运行Docker |
| 幂等key永久清理好了 | 保留建议不代表已实现清理任务 |

## 30秒检查清单

说“实现”时找到代码；说“通过”时找到实际证据；说“优化”时拿出前后指标；说“我负责”时说明上游和AI辅助边界；讲未完成能力时显式使用“规划/待实现”。
