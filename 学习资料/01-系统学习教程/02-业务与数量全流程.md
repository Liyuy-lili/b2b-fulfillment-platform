# 02 业务与数量全流程

> 最终集成（2026-10-20）：最终闭环还含执行事件/Inbox与版本、CSV去重/文件下载、READ账号和0差异核对，见30；原M3/M4.2样例仍为各自真实历史数据集。

## 1. 业务角色

办公耗材供应商有销售、履约和仓库人员。销售单回答客户买什么/多少/多少钱；履约一对一扩展回答预留哪些仓、发出多少、取消多少。租户是公司边界；同名商品也不能跨租户共享库存。

## 2. 三组公式

库存维度是“租户+商品+仓库”：

```text
H = erp_stock.count                      实物账面库存
R = erp_stock.ful_reserved_count         尚未消费的预占汇总
A = H - R                               可用库存
H >= R >= 0

ordered = open + reserved + shipped + cancelled
0 <= returned <= shipped

allocated = held + consumed + released
```

第二组按订单项计算；第三组按预占记录。不同商品的箱和千克不能相加为可发货量。returned独立记录，不能从历史shipped里减。

## 4. 动作的不同含义

| 动作 | 数量去向 | H |
| --- | --- | --- |
| 手动释放 | reserved→open，仍需履行 | 不变 |
| 自动到期 | reserved→open，待重新分配 | 不变 |
| 取消 | open/reserved→cancelled | 不变 |
| 发货 | reserved/held→shipped/consumed，R减少 | ERP减少 |
| 退货申请 | 占可退额度，不等于到货 | 不变 |
| 退货收货 | returned增加，shipped不变 | ERP增加 |

## 5. 状态的三个维度

OrderStatusCalculator按行归纳，不任意拼状态。

| 状态 | 含义 |
| --- | --- |
| NEW | 尚未尝试分配 |
| WAIT_STOCK | 尝试后仍有open、尚未发货 |
| RESERVED | 未结束量已预占、尚未发货 |
| PARTIALLY_SHIPPED | 已发一部分且仍有open/reserved |
| FULFILLED | 全部发出 |
| CANCELLED | 全部取消且未发货 |
| PARTIALLY_CLOSED | 发货加取消覆盖订购量 |

发货单SHIPPED/DELIVERED是配送维度；退货单REQUESTED/RECEIVED/REJECTED是逆向维度。签收不修改商业订购量，退货不抹掉历史发货。
