# ADR-009：M0 本地运行与基座收敛

> 阅读语境：以下正文记录该阶段当时的实现和取舍，早期“后续待做”仅为历史状态。当前M0—M7已经完成，请结合[现行总目录](../README.md)与系统教程。工程验收原件未改。

日期：2026-10-16。状态：已实施；验收证据见 M0 报告。

## 问题

本机无 Docker/Maven PATH，有既有 MySQL 8.0 服务；工作区含中文路径。上游前端包含未启用模块的构建入口及镜像包 URL。基础 SQL 没有 ERP 业务建表语句。

## 决定

- 固定前后端 SHA 不变、Java 17 / Boot 3.5.15 不变；开启 ERP 根模块和启动依赖。
- 本地使用独立 MySQL 8.4.6（33306）和社区 Windows Redis 7.2.8（36379），仅监听回环地址；不接管既有系统服务。
- Redis 开启 AOF everysec 与 RDB，单独保存到 `.local/redis-data`；正常停止使用 shutdown save。基座单号由 Redis INCR 生成，不能把它当成可任意丢弃的纯缓存。崩溃后最多一秒 AOF 窗口及 Redis 数据丢失恢复问题仍需单独处理；不宣称单号绝对不丢。
- Windows Redis 来自 redis-windows 社区 MSYS2 构建，不能称为官方 Windows 发行版。Compose 指向官方 Linux MySQL/Redis 镜像并锁定 digest，但本机未执行容器验收。
- Maven Wrapper 3.3.4 下载 Maven 3.9.16 并核验 SHA256；Node 实测 24.18.0；pnpm 固定 9.15.9。
- 前端锁文件只规范化 159 个下载地址为 npm 官方 registry，保留解析版本和 integrity；使用 frozen-lockfile 安装。
- 菜单保留 system/infra/ERP，动态与静态路由也同步收敛；未启用业务源码保留以便比较，不参与页面路由编译。
- 新增 fulfillment 配置，不使用上游 local 配置中的外部示例账户。文件存储使用本地数据库，社交/短信示例通道禁用。system 仍需要的微信 SDK Bean 使用占位配置。
- 补齐全部 33 张 ERP 表，统一 DECIMAL(24,6)，可选 ID 缺省 NULL，公共审计/逻辑删除/租户列齐备；每次初始化只允许新建项目数据库。
- Windows 使用英文 Junction 访问 MySQL 程序与数据；Java 启动 Jar 副本，避免占用 target 构建产物。

## 影响

库存事实来源、交易边界、消息语义均未改变。M0 不承诺并发流水余额正确、历史数据迁移兼容或生产安全配置；M1/M2 继续按规范完善。当前仅适用于本地演示环境，外部部署必须重新配置账户与网络。
