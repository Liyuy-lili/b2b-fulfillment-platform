# ADR-011：M2 预占与统一库存写入

> 阅读语境：以下正文记录该阶段当时的实现和取舍，早期“后续待做”仅为历史状态。当前M0—M7已经完成，请结合[现行总目录](../README.md)与系统教程。工程验收原件未改。

日期：2026-10-18。状态：已实施并验收。

- M2 已获用户“继续”授权。保留固定基座、同库事务与 ERP 实物库存唯一来源；分配/释放仅修改 R、预占、履约项和预占流水，不扣 H。
- V1 与 M0 SQL 保持不变。V2 增量加入 R、H/R/删除约束、预占关联/active 约束和新权限；迁移前检查重复、负数、已删除库存，脏数据列出并中止，不自动合并。
- ERP 新增库存锁投影与商品/仓库锁键，不改变 M0 实体清单。所有实物变化入口构建完整流水请求批次，先按 product/warehouse 升序创建/锁定库存，再执行原有逐行变化；缺失库存通过唯一键 upsert 后当前读。预占时缺失行视为零，不创建承诺。
- 明确兼容边界：旧 ERP 单据自身的源单/单据状态锁仍在库存锁之前（原审核 CAS 与 M1 关联重检保留），不能宣称所有表已严格按原规格的绝对顺序重排。M2 履约命令不锁或修改这些未托管 ERP 出入库单据，双方共享的库存锁均按同一升序取得；旧流程不在写完一行库存后才发现下一行锁。M3 适配器创建新单据，并继续禁止手工修改托管出库，需重新审查跨模块锁依赖。
- 新增 R 通过条件更新保证 0≤R≤H；旧 ERP 每次改变 H 均检查新 H≥R。库存余额使用当前读与 BigDecimal，不经 double；库存行无删除业务入口，CHECK 拒绝逻辑删除。
- PRIORITY_SPLIT 按仓库 sort/id 排序；SINGLE_FIRST 优先单仓满足整单，否则回退。重复商品需求共享库存余量，不混合不同商品单位。所有 open 全量满足才提交，否则正常记录等待状态且不增加预占。
- SKU 基本单位创建后不可修改（更正需新 SKU），避免已有 H/R 与订单快照的单位被主数据编辑重解释；不支持跨单位换算。分配仍校验快照单位与商品一致。
- 分配仓库由请求明确给出，最多 16 个，服务端验证本租户启用仓库。M2 权限为功能权限+订单归属+租户边界；M6 再接仓库授权表，不把当前租户内全仓可用说成细粒度仓库权限。
- 释放按预占记录指定正数量，reserved 转回 open，held 转 released，R 同量下降；不改变 ordered、shipped、cancelled。手工释放允许处理过期记录；自动到期扫描与发货到期校验在 M4/M3 接入。
- 绑定/分配/释放共用命令记录服务与最外层有界重试原则。重试仅针对数据库锁失败，最多 3 次，每次重新进入整个事务，短随机退避；已经加入外层事务时不在内部重试。旧 ERP 事务入口以同一重试组件包裹，不拆分提交。
- 新接口暂由 HTTP 验收，现有 M1 页面保持；完整分配工作台在 M3。不提前引入发货、Outbox 或消息语义。

验收已完成：策略与重试单测；真实 MySQL 双实例同键、有限库存竞争、整单不足回滚、重复商品、精度、释放、旧减少入口与撤销、首次建行、库存与流水恒等式、M1/M0 回归、从零安装和完整依赖重启。实际命令、结果与限制见 [M2 验收报告](../10-验收证据/M2-验收报告.md)。
