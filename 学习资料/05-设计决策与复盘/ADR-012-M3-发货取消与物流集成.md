# ADR-012：M3 发货、取消与物流集成

> 阅读语境：以下正文记录该阶段当时的实现和取舍，早期“后续待做”仅为历史状态。当前M0—M7已经完成，请结合[现行总目录](../README.md)与系统教程。工程验收原件未改。

日期：2026-10-18。状态：已实施并验收（2026-10-19）；用户“继续”授权推进 M3。

- 固定基座、ERP 实物库存事实来源、同库 REQUIRED 事务和消息语义保持。M3 不引入 MQ/Outbox，也不把物流签收当作出库。
- 发货锁顺序为命令→ERP 源单→履约主/明细→预占→有序库存→本次新建的 ERP 出库。发货只限一个启用仓库、正数量、当前订单未到期 held。先 R/held 转 consumed，再由 ERP 库存流水唯一扣 H，所有写入同事务提交。重放先检查当前权限与归属，不再检查已经消费或过期的原预占。
- ERP 提供仅供 Java 调用的内部创建并审核端口，强制 MANDATORY 传播；内部验证托管关系、源单审核、商品/单位/源明细映射。控制器 DTO 不新增绕过字段，不使用全局 ThreadLocal 放开旧入口。正常手工创建、编辑、反审核、删除仍拒绝托管源单。内部同步 ERP 出库累计使用专用受控方法，复用原数量上限检查。
- 金额沿用 ERP MoneyUtils 的逐出库明细/税额/优惠规则；商品、价格、税率和商业字段来自冻结源单与履约快照。不同商品单位不合并解释为可发货总量。
- 取消先减少 open，再按预占 ID 升序释放 held，reserved 转 cancelled；open 转 cancelled。以订单项逐行记录本次取消和原因，H 不变。取消与发货由相同源单/订单锁串行。旧 ERP 查询增加逐行待履约量口径，不能把取消数量显示为待发货；商业订购数量不改写。
- 预览只读、不持有库存写锁、不创建命令或预占，返回策略版本、H/R/A 和计划；正式分配仍重算。前端沿用 Element Plus 操作后台，保留字符串数量与 ID，客户端不使用 Number 做业务数量运算。失败后相同内容保留幂等键，修改内容才生成新键。
- 物流匿名回调按服务端 integrationId 映射租户/provider/密钥，覆盖不可信租户上下文，并校验租户有效。HMAC-SHA256 签名为 timestamp + 换行 + eventId + 换行 + 原始 body，五分钟偏差，常量时间比较。header eventId 必须与 body 相同。事件摘要不包含签名时间。
- 回调锁事件唯一键后锁同租户发货；签收只单向从 SHIPPED→DELIVERED。重复返回原结果，迟到运输中事件仅记录；同 ID 不同内容记录冲突次数/摘要并返回冲突。未知发货保留日志诊断并返回可重试业务错误，不创建孤立事实。模拟器在管理接口鉴权/归属校验后，通过本机真实 HTTP 发出签名通知，不在业务事务内发 HTTP。
- M3 权限延续功能+租户+订单归属；仓库必须属于当前租户且启用，细粒度仓库授权仍由 M6 实施。自动释放过期预占、退货、定时核对为 M4，发货现在必须拒绝过期预占。
- V1/V2 不修改，新增 V3 保存取消事实、发货关联约束、物流事件字段和权限。验收覆盖真实双 JVM、重复发货、部分发货、取消竞争、ERP 审核后失败回滚、旧入口冻结、到期拒绝、回调验签/重复/乱序/冲突/错误集成、页面和旧阶段回归。

实际进度以 PROJECT_STATUS 与执行证据为准。
