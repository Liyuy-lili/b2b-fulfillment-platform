# ADR-015：快照核对与差异追溯

> 阅读语境：以下正文记录该阶段当时的实现和取舍，早期“后续待做”仅为历史状态。当前M0—M7已经完成，请结合[现行总目录](../README.md)与系统教程。工程验收原件未改。

日期：2026-10-19。状态：已实施并验收，执行证据见M4.3阶段报告。

## 决策与范围

1. 当前同步执行全租户核对，只授予专门审计操作人员。执行同时要求query/run权限；查看仅限当前租户、本人发起的报告，确认还需review权限。此权限意味着可见本租户全范围库存和订单审计事实，不能给普通订单所有者自动继承。没有客户端tenant/actor/warehouse/owner绕过参数；仓库细粒度授权仍为M6。
2. 外层20秒RC事务claim命令并原子保存报告/全部差异，失败全部回滚；独立Bean通过REQUIRES_NEW启动15秒只读RR事务，首次普通InnoDB读取erp_stock建立read view，17张业务事实表均为普通SELECT，绝不FOR UPDATE或改写。权限查询和等待同key命令不会提前建立事实快照，也不会导致重放看不到刚提交的报告。REQUIRES_NEW只读取事实，不提交任何库存副作用；普通业务写事务保持RC。一次核对同时占用两条连接，当前连接池需保留余量。命令行锁仅属于本次命令，不获取源单、订单或库存行锁。
3. snapshotAt是首次业务读取前的数据库UTC时间标记，不是精确的事务提交边界，也不按create_time过滤数据。之后并发提交在本次快照外，下一次新key扫描才可见。规则版本M4.3-v1。相同key返回原报告，即使事实已改变也不隐式重扫；新key产生新报告。
4. 每表按tenant_id/id索引、id游标、每批最多200读取。普通表最多2000行，两类流水每表最多10000行，最多2000差异；每表额外读取1行探测超限。任一上限或事务超时失败，不保留部分报告、不返回“无差异”。上限不能经HTTP调高；当前同步全租户规模有明确边界，不宣称大规模审计服务。V5为缺少tenant/id前缀的11表新增索引，其他6表复用既有uk_tenant_id；独立库验证后才升级主库。
5. H核对ERP全部正负流水，R分别核对held和预占流水；不能叠加实物与预占流水。库存身份从库存/ERP流水/预占/预占流水并集取，汇总行缺失即使净量0也要报告。核对逐项订单量、状态、预占、发货/取消/退货、ERP源单投影及双向单据映射。托管关联限定本租户，非托管ERP单据不要求履约映射。
6. 报告是已完成观察记录，无RUNNING后台任务，也不宣称持久化失败任务。差异保存规则、对象、关联ID、期望/实际字符串和说明。人工确认只OPEN→ACKNOWLEDGED，可追加多条带操作者/UTC时间的说明；确认不表示数据已修复。新扫描产生新报告，不覆盖旧报告或自动改原差异状态。没有库存修复、删除报告、撤销业务事实API。
7. 测试profile支持JDBC命名锁屏障（首次库存读取后）和报告插入后异常，用来验证真实并发快照与报告原子性。默认profile没有这些Bean，HTTP没有故障或屏障参数。故意污染仅在新独立测试库、明确记录恢复，绝不改主库演示事实。
8. 控制器在获取任何事务连接之前使用本JVM单名额Semaphore，最多等待5秒，忙时返回1080000052并允许原key重试，避免多个外层事务耗尽连接池后全部等待内层连接。它控制扫描资源，不取代跨JVM数据库命令幂等，也不用于库存互斥。普通业务和报告查询不占这个名额。

## 与初始规格差异

初始规划的cutoff/status/RUNNING作业收敛为同步完整快照报告；不提前引入M5/M6持久化调度器。新增ful_reconcile_review记录人工说明，而非用“已修复”状态掩盖差异。改变的是核对读取事务隔离；库存来源、业务写事务、消息语义与固定基座保持。两份主文档同步本决策；实际结果以PROJECT_STATUS与阶段报告为准。
