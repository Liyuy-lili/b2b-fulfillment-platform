# ADR-014：退货申请、收货与ERP唯一入库

> 阅读语境：以下正文记录该阶段当时的实现和取舍，早期“后续待做”仅为历史状态。当前M0—M7已经完成，请结合[现行总目录](../README.md)与系统教程。工程验收原件未改。

日期：2026-10-19。状态：已实施并验收。范围M4.2；M4.3核对尚未实施。证据见 [M4.2验收报告](../10-验收证据/M4.2-验收报告.md)。

- 固定基座与库存事实来源保持。申请/收货/拒绝分别使用独立持久化命令，同库RC事务，事务代理外最多3次数据库锁失败重试。没有HTTP绕过字段或REQUIRES_NEW。
- 一个申请对应一个原发货单，只退回原仓。订单锁内校验同一发货项的REQUESTED+RECEIVED+本次<=原发货量。REJECTED释放可退额度；REQUESTED不增加H。
- 锁顺序：命令→ERP源单→履约订单/明细→发货主/明细→退货主/明细→有序库存→本事务新建ERP退货。物流回调只锁事件/发货，不反向锁订单/库存。ERP源单托管后不可改，原出库不可反审核/删除，适配器读取其已冻结商业字段。
- ERP定义仅Java调用的 `ErpManagedSaleReturnPort`，MANDATORY加入履约事务。服务端从原ERP已审核出库项取得仓库、产品、基本单位、源项、价格和税率，复用原退货创建、金额计算、审核、库存流水和累计数量更新。原ERP公共创建/修改/撤销等入口仍冻结托管源单。
- 退货项关联原履约发货项、ERP退货项和ERP实物流水。H只由ERP审核写入一次，R不变，不额外写预占变化流水。returned增加，gross shipped和open/reserved/cancelled保持，履约结束状态不回退。退货不等于退款；ERP refundPrice保持0。
- 新V4仅增加退货事实表、租户/同订单/同发货关联约束及权限，V1—V3不修改。申请和终态不可删除；收货/拒绝为互斥终态。同key重放原结果，不同key对已收货再收货返回既有结果，不再次入库；收货已拒绝申请或拒绝已收货申请报冲突。
- 权限沿用功能+租户+订单归属。页内提供申请/收货/拒绝和分页历史，数量与ID仍为字符串；细粒度仓库授权保持M6范围。
- 专用测试profile验证ERP库存批次内部故障和ERP返回后故障，事务全部回滚后用原key恢复；另验证超量/并发申请、双JVM重复收货、收货/拒绝竞争、权限撤销后重放、旧入口冻结、新库/升级和重启。

实际执行双JVM核心71、最终API22、ERP110、新库绑定68、升级25、约束10、浏览器SQL21、完整重启/重放12及37指定单测，前端定向检查/构建与两轮桌面/手机检查通过。V4已执行，后续不得修改。每份申请按其明细一次性收齐，分次退货建立多申请，不开放终态撤销；无资金退款、跨仓退回或自动补发。
