## 3. 核心事务与失败证据

- 预览稳定地按仓库优先级输出计划和策略版本，不创建命令或 R。
- 同一仓库部分发货，未到期 held 才能消费；重复 reservationId、零量、超量、其他仓库或其他订单记录拒绝。
- 跨两个正常 JVM 的 6 个同 key 发货请求返回同一响应，只建立一张 ERP 出库和一份发货事实；等值十进制请求可重放，改数量冲突。
- 发货/取消三轮竞争中，仅一方能完成相互冲突的数量请求，后获得锁的一方按最新额度拒绝，最终数量恒等式保持。
- 预占真实等待 60 秒到期后拒绝发货，H/R 不变；手工释放仍可执行。自动扫描尚未实现。
- ERP 审核后失败、ERP 审核内部库存批次后失败分别验证回滚：H/R、held/consumed、订单汇总、ERP 出库及明细/流水、发货、预占流水、命令记录都恢复到操作前。
- 相同 key 在正常实例重新执行成功，再重放无重复效果。故障点只由隔离测试 profile/启动参数启用，没有 HTTP 请求故障开关。
- Redis 单号不是 MySQL 事务的一部分，失败允许留下编号空档，没有把连续编号当成回滚要求。
- 旧销售单查询返回托管标志和逐项 `open+reserved`/cancelled 字符串投影；取消量不作为待发货量展示，源商业数量不改写。

## 4. 物流与权限证据

- HMAC 校验原始请求字节、timestamp 与 eventId；header/body 的事件 ID 一致，业务摘要排除签名时间。
- 同事件重放返回原结果；已签收后运输中事件仅记录；同事件不同内容返回冲突，次数和最后冲突摘要在独立业务事务提交后保留。
- 错签名、过期签名、未知 integrationId 拒绝。未知发货返回可重试业务错误并记日志，不创建孤立发货。
- 使用本租户集成密钥签名、却指向另一租户的发货，仍然查不到；租户头不能把集成切到其他组织。
- 管理命令按当前功能权限、租户和源单归属判断，重放同样检查当前权限；撤权后不能靠旧 key 重放。
- 本地模拟器真实发 HTTP，成功经过同一匿名回调入口；回调前后 H/R 保持。页面正常显示出库履约与物流配送两种状态。

## 6. 迁移与复现

V3 在已停用旧应用时增量加入发货关联约束、取消事实表、物流事件字段和权限；V1/V2 不修改。主库为 `fulfillment`，新独立库为 `fulfillment_m3_clean_20261018`，后者验收使用 48081 与 Redis DB3，结束后停止自己的进程。M1/M2 的独立库并不因此自动宣称已升级 V3。

```powershell
# 已配置过且完成迁移的本机
./scripts/Start-Local.ps1
# 两个正常实例 + 一个隔离审核后故障实例；最后停止测试实例
./tests/m3_instances.ps1
# ERP 审核内部故障 + 历史阶段回归（不要与上一组并行运行）
./tests/m3_instances.ps1 -FaultDuringErp -TestFiles m3_erp_failure.py,m3_previous_inventory.py
# 暂停业务写入，确认测试实例已停止，再做完整依赖重启
python tests/m3_restart.py
```

`m3_migration.py` 是首次升级试验，不能在已升级库上重复断言“当前仍为 V2”。日常使用 `Migrate-Database.ps1 -Action validate`；不自动 clean/repair，不覆盖已有库。

实际后端打包指定 `OrderStatusCalculatorTest,AllocationPlannerTest,DatabaseCommandRetryTest,LogisticsSignatureTest`，加 `-Dsurefire.failIfNoSpecifiedTests=false`。`Build.ps1` 仍跳过上游单测，不能把常规打包误报为全部测试通过。

历史回归使用独立的 M3-* 证据文件；M2 脚本新增可选证据路径/日志路径参数，保留原默认行为和原 M0—M2 报告。ERP DDL 生成器/基座来源/许可证在最终检查中核对。

## 7. 限制与修正记录

- 采用同库模块化单体与本地事务；没有生产物流或跨库分布式事务。可配置的物流密钥有公开本地默认值，共享部署需替换。
- 细粒度仓库授权、字段范围、异步任务审计仍在 M6；当前是功能+租户+订单归属，以及本租户启用仓库检查。
- 预占自动到期、退货和定期核对仍在 M4；本轮只做发货时的到期拒绝与手工释放。Outbox/MQ 在 M5。
- 发货列表按订单分页；取消和物流事件各展示最近 100 条，预占历史仍为按单查询。更大历史量与查询批量优化待后续扩展。
- 保留 ERP 金额舍入和部分上游 UI/类型问题；未做全量 TypeScript 清理、无障碍认证、Docker 运行或压测。
- MySQL 8.4 高于固定 Flyway 提示的最高测试版本 8.1，本机迁移和启动实际通过；没有擅自升级 BOM。
- 初版测试脚本引号与错误枚举已按实际代码修正后复验。升级脚本的 Windows 子进程管道 EOF 等待改为日志文件输出，不把管道等待误判成业务失败。
- 本轮续接时发现服务未在监听，首次重启检查在读快照前连接失败；随后重新启动本地依赖并重新执行门禁，最终结果单独记录，不把该次失败算作通过。
- 仍无本地 Git 提交、推送或 PR；保留固定来源与许可证，当前工作区代码为本地改造。
