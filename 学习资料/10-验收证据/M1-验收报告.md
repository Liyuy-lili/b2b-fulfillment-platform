### 2.1 可重复执行的日常回归

先完成构建，并确保正在运行的后端是本次产物：

```powershell
./scripts/Build.ps1
./scripts/Stop-Local.ps1
./scripts/Start-Local.ps1
python tests/m1_acceptance.py
python tests/m1_locking.py
python tests/m0_smoke.py
```

领域单测（在 `backend` 目录，PowerShell 下参数保留引号）：

```powershell
./mvnw.cmd -B -ntp -pl yudao-module-fulfillment -am test '-Dtest=OrderStatusCalculatorTest' '-Dsurefire.failIfNoSpecifiedTests=false'
```

完整依赖重启验收：先暂停业务写入、关闭编辑表单，再运行 `python tests/m0_restart.py`。脚本保留原 M0 检查并补充了 M1 持久化检查。需要 PowerShell 7；找不到时通过环境变量 `M0_PWSH` 指定可执行文件。

每次业务回归新增有独立前缀的数据、用户、角色与测试租户，不自动删除。`m1_locking.py` 使用主库上一次验收的 fixture，读取本机独立 MySQL root 的会话列表控制交错；不是面向生产运行的脚本。

### 2.2 首次迁移验收与普通校验的区别

`tests/m1_migration.py` 是初次接管验收，要求两个目标库仍处于 M0，不能直接在已经迁移的库上重跑完整首次接管流程。它确实验证了：

- 未 baseline 的非空库 migrate 被拒绝。
- 基座额外字段导致 baseline 被拒绝；测试字段随后恢复。
- baseline 0 → migrate V1 → validate；重复 migrate 不重复写入。
- 原有 81 表的行数不变，只有菜单表按 V1 增加两行。
- 已迁移库不能再次按 M0 接管。
- 独立库历史 checksum 被暂时改动时 validate 失败，恢复原值后校验通过。

日常只运行 `./scripts/Migrate-Database.ps1 -Action validate`。不提供自动清库或自动 repair。

独立库启动验收入口为 `tests/m1_clean_install.ps1`，默认库 `fulfillment_m1_clean_20261017` 必须已完成初始化和迁移。它使用单独端口和 Redis DB1，运行结束停止自己的 Java 进程。

## 3. 正确性检查覆盖

### 绑定与回滚

- 相同键重放、不同键绑定同一源单，返回同一履约编号。
- 相同键对应不同源单被拒绝。
- 8 个不同键竞争同源单；6 个同键竞争命令记录。
- 草稿源单拒绝，命令记录回滚；审核后相同键可成功。
- 第二条源单明细数量为 0，前面已经插入的履约头/第一条明细/命令记录一起回滚。
- 新 API ID、金额、数量为字符串，时间为 ISO 偏移字符串。
- 源单任意出库/退货历史（包括逻辑删除记录）阻止接管。

### 旧入口与并发

- 托管源单编辑、反审核、删除拒绝。
- 手工出库、退货创建及将已有出库单改挂到托管源单拒绝。
- 绑定与旧出库创建并发：允许且只允许一边成功；另一边得到托管或源单已使用错误。
- 两请求同改出库单关联：等待后检测父单变化，只有一个新源单被计数。
- 等待期间源单完成绑定：旧请求重新检查后拒绝，单据仍属于原源单。
- 绑定与拒绝的旧写入没有改变 ERP 实物库存和库存流水。

### 权限

- 匿名、无新功能权限、非创建者、跨租户已知 ID 访问拒绝。
- 普通创建者可绑定和查询自己的单；分页不返回其他创建者的数据。
- 当前租户超级管理员 / 租户管理员可管理租户内订单。
- 撤销绑定权限后，重放已成功命令也被拒绝。
- 其他租户创建自己的基础数据并成功绑定，证明跨租户测试没有靠全盘拒绝请求通过。
- 伪造 body 中 tenant/owner/status 不会改变服务端归属；token 与租户请求头错配拒绝。

## 4. 实际定位和修复的问题

1. **Flyway 与连接池。** 可选权限探测被 MySQL 拒绝，Druid 丢弃连接导致迁移后续失败。改为同凭据的独立短连接，不增加数据库权限。
2. **新时间字段序列化。** 初版响应被基座全局设置变成数字，改为显式 ISO 时间字符串，不改旧 API。
3. **缺少幂等请求头。** 初版被基座异常处理转为 500，改为可空绑定配合非空约束，真实请求返回参数错误。
4. **RR 间隙锁死锁。** 控制旧事务与新绑定的锁等待后复现。默认统一 RC 并校验实际业务连接，重跑通过；详见 ADR-010 与讲解文档。
5. **验收工具假设。** JDBC 等待可能出现在优化器统计阶段，`innodb_trx` 不能稳定给出等待行，改为读取实际挂起的源单锁 SQL；独立应用 readiness 初版假设 `/actuator/health` 存在，改用真实登录验证就绪。这些初版工具失败不计为通过。
6. **窄屏详情。** 初版双列描述在窄屏挤压，改为单列；数量表保留横向滚动。首次过渡帧截图作废，布局稳定后重新采集。

失败后的修改、复验和剩余限制均在本报告说明，没有将初版执行失败写成最终通过。
