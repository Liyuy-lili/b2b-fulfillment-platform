## L01 为什么旧出库必须改？

**短答：**引入R后只看H足够会消耗已承诺库存，普通减少应保证H+delta≥R。

**展开：**H10/R8普通出5会破坏承诺，只能出2。履约入口正确不能抵消旧调拨、盘亏等入口的写入。

**继续追问：**列出所有可能减少H的业务。

**易错：**只保护新增预占API。

**定位：**`ErpStockMapper.changePhysical`；结合阶段报告中的实际场景与证据。

## L02 八类旧入口具体是哪八类？

**短答：**采购入库、采购退货、销售出库、销售退货、其他入库、其他出库、调拨、盘点。

**展开：**还要看反审核/撤销的反向效果，原来增加H的动作撤销时也可能消耗已承诺量。调拨涉及两仓。

**继续追问：**采购入库反审核为何受R限制？

**易错：**只统计审核正向入口。

**定位：**`M2-stock-writers.json / m2_legacy_inventory.py`；结合阶段报告中的实际场景与证据。

## L03 公共库存流水为什么批量锁？

**短答：**先收集本次所有StockKey，去重排序后拿锁，再逐行改H和写流水。

**展开：**避免业务明细顺序不稳定造成A→B与B→A反向取锁；原有业务状态锁仍位于库存前，不声称重排所有旧表。

**继续追问：**调拨两仓反向并发如何处理？

**易错：**处理一行才发现下一个锁。

**定位：**`ErpStockRecordServiceImpl.createStockRecords`；结合阶段报告中的实际场景与证据。

<a id="l04"></a>

## L04 为什么流水余额也会错？

**短答：**若用事务早先普通读的旧余额生成total_count，实际库存更新虽成功，流水仍可能记录错误余额。

**展开：**公共服务当前读锁定最新库存，再计算并返回精确after给流水，SQL SUM不经double。

**继续追问：**库存表对了就可以不核对流水吗？

**易错：**只检查最后余额。

**定位：**`ErpStockServiceImpl.updateStockCountIncrement`；结合阶段报告中的实际场景与证据。

<a id="l05"></a>

## L05 第一次入库同时建库存行怎么办？

**短答：**使用tenant/product/warehouse唯一身份ensure，冲突后重读锁同一行，避免两条库存身份。

**展开：**真实入库createMissing=true；预占false，缺失是零。数据库唯一键而非查无结果承担最终身份约束。

**继续追问：**为什么不能逻辑删后重建？

**易错：**依赖不存在记录的锁读代替唯一性。

**定位：**`ErpStockMapper.ensure / V2`；结合阶段报告中的实际场景与证据。

<a id="l06"></a>

## L06 负数量草稿为什么危险？

**短答：**负出库取反会变成增加H，可能凭空制造库存。

**展开：**当前在库存生效边界检查自然数量正值；盘点差额可正负但实际和账面非负、差额一致。并未声称全部草稿保存规则重写。

**继续追问：**审核失败时状态应怎样？

**易错：**只在前端input上设置最小值。

**定位：**`旧ERP审核服务 / m2_legacy_inventory.py`；结合阶段报告中的实际场景与证据。

<a id="l07"></a>

## L07 撤销入库会破坏什么？

**短答：**原入库后的货可能已被预占或使用，撤销不能无条件减少H到R以下。

**展开：**H20/R15撤销10应拒绝，事务回滚审核状态与库存效果。撤销不是绕过当前可用量的特殊通道。

**继续追问：**反审核与预占同时到达谁成功？

**易错：**认为撤销只恢复旧值无需校验。

**定位：**`ErpStockServiceImpl / 旧业务反审核`；结合阶段报告中的实际场景与证据。

<a id="l08"></a>

## L08 商品基本单位为什么冻结？

**短答：**历史预占、订单快照和库存按原基本单位解释，变更单位会让同一数值含义改变。

**展开：**当前不实现箱/件换算；单位改造需要额外换算和迁移规则，不能只改商品展示字段。

**继续追问：**从箱改件怎么保证历史可解释？

**易错：**数量没变就认为数据没变。

**定位：**`ErpProductServiceImpl / M2决策`；结合阶段报告中的实际场景与证据。

## L09 原ERP已经有条件扣库存，你新增什么？

**短答：**新增预占R约束、所有旧入口可用量保护、有序批次锁、当前读精确流水和并发/异常验证。

**展开：**准确说明上游已提供库存事务和条件更新，项目把原实物边界扩展成承诺边界，并保留原单据与金额逻辑。

**继续追问：**给出一个改造前后失败例子。

**易错：**说原框架完全没有并发保护。

**定位：**`ErpStockMapper / M0与M2报告`；结合阶段报告中的实际场景与证据。
