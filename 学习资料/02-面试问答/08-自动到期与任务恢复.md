## E01 当前定时任务用什么？

**短答：**Spring独立单线程scheduler，本机Quartz未启用。

**展开：**默认批50、每轮最多4批、fixedDelay5秒；这是轮间延迟，不是处理时延SLA或每5秒必完成200条。

**继续追问：**为什么没有直接复用Quartz？

**易错：**按旧规格声称已经使用Quartz集群。

**定位：**`ExpirySchedulingConfiguration / ADR-013`；结合阶段报告中的实际场景与证据。

<a id="e02"></a>

## E02 为什么不靠Redis TTL释放库存？

**短答：**释放涉及多个MySQL事实，需要可重扫的持久化候选和同库事务。

**展开：**过期通知可能重复/错过或进程离线，不能替代R/held/open/ledger共同提交。当前基于数据库期限扫描。

**继续追问：**停机期间过期怎么办？

**易错：**把缓存过期等同业务库存回滚。

**定位：**`FulReservationMapper.scanExpired`；结合阶段报告中的实际场景与证据。

<a id="e03"></a>

## E03 扫描为什么不先FOR UPDATE预占？

**短答：**前台锁序是源单/订单再预占，扫描先锁预占会倒序扩大死锁风险。

**展开：**全局无锁候选只是提示，逐条到事务再锁和复核。取得候选不等于拥有业务处理权。

**继续追问：**两个实例都看见候选怎么办？

**易错：**以扫描器锁定记录保证只运行一次。

**定位：**`FulExpiryScanner / FulExpiryService`；结合阶段报告中的实际场景与证据。

<a id="e04"></a>

## E04 系统任务怎样处理租户与审计？

**短答：**逐候选验证租户有效，TenantUtils包裹并恢复上下文，内部EXPIRE命令actor0。

**展开：**不伪造管理员登录，不开放HTTP系统入口或客户端绕过字段；无效租户保留，恢复有效后补扫。

**继续追问：**异常后上下文怎么清理？

**易错：**用一个全局忽略租户状态跑所有写入。

**定位：**`claimExpiry / FulExpiryScanner`；结合阶段报告中的实际场景与证据。

<a id="e05"></a>

## E05 坏首行为什么不阻塞后页？

**短答：**游标按expireAt/id推进，即使该条失败也继续，到尾回绕再重试。

**展开：**游标仅扫描位置，不是成功记录；每轮有界防无限扫描，单条锁超时仍可能拉长耗时。

**继续追问：**每轮只LIMIT最早N条会怎样？

**易错：**失败不前进导致后页饿死。

**定位：**`FulExpiryScanner.scan`；结合阶段报告中的实际场景与证据。

<a id="e06"></a>

## E06 期限为什么拿完库存锁再查？

**短答：**等锁可能跨过到期时间，必须以最终写决策时刻复核。

**展开：**发货与到期都使用UTC新now。历史测试让发货持预占等库存跨期限，最终拒绝发货，无ERP效果。

**继续追问：**进入方法时没到期够不够？

**易错：**用缓存的请求开始时间判断。

**定位：**`FulExecutionService.ship / M4.1核心`；结合阶段报告中的实际场景与证据。

<a id="e07"></a>

## E07 未来期限候选为什么抛异常回滚？

**短答：**若持久化未到期的终态no-op，同一reservation系统key以后真正到期会一直重放旧结果。

**展开：**CandidateNotDueException回滚本次claim；已关闭预占可保存ALREADY_CLOSED，因为旧记录未来不会重新打开。

**继续追问：**重新分配会复用原reservation吗？

**易错：**所有无操作都存成最终成功。

**定位：**`FulExpiryService.expire`；结合阶段报告中的实际场景与证据。

<a id="e08"></a>

## E08 双实例如何只释放一次？

**短答：**命令唯一键及共享源单/订单/预占/库存锁串行，后者重放或看到已关闭。

**展开：**允许重复扫描和日志结果重复，最终只一条数量效果和EXPIRE流水。单线程只在单实例内成立。

**继续追问：**需要全局分布式调度锁吗？

**易错：**日志两条就认定重复扣量。

**定位：**`M4.1-expiry-acceptance.json`；结合阶段报告中的实际场景与证据。

<a id="e09"></a>

## E09 重启后游标丢失会怎样？

**短答：**从初始位置重扫持久化未结束候选，数据库幂等和状态保护正确性。

**展开：**游标不是业务事实，重新扫已关闭记录不会重新释放consumed。到期扫描本身不使用任务租约；M5发布/M6文件另有owner/version/live协议，不能混为同一机制。

**继续追问：**停机积压能保证多久清完吗？

**易错：**给未经压测的恢复时延承诺。

**定位：**`FulExpiryScanner / 新JVM补扫证据`；结合阶段报告中的实际场景与证据。

<a id="e10"></a>

## E10 到期如何验证，哪些没验证？

**短答：**自然60秒、双JVM、故障回滚、坏首行后页、跨期限发货、竞争和新进程补扫均有历史证据。

**展开：**一些安排竞争的fixture只修改期限，不能说全部自然等待；未验证跨机偏差、全部崩溃窗口或积压SLA。

**继续追问：**正常重启等于突然断电吗？

**易错：**把实验范围扩大成全场景证明。

**定位：**`M4.1-验收报告`；结合阶段报告中的实际场景与证据。
