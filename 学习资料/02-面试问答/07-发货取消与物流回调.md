## S01 发货为何同时降低H和R？

**短答：**R是尚未发出的承诺，发出后需消费；H表示在库货，出库也要减少。

**展开：**同事务先改held/R再ERP审核扣H，库存锁保持，中间可用量不会被另一个写命令消费。

**继续追问：**为什么不能分两个事务？

**易错：**先独立释放再异步扣H。

**定位：**`FulExecutionService.ship`；结合阶段报告中的实际场景与证据。

<a id="s02"></a>

## S02 如何保证实物只扣一次？

**短答：**履约不直接改H，通过ErpManagedSaleOutPort由ERP库存流水服务唯一执行。

**展开：**发货事实保存ERP出库项和实物流水映射；同key重放不再调ERP，公共托管出库仍冻结。

**继续追问：**如果ERP审核后再手动减H呢？

**易错：**以为双重扣减多一道保险。

**定位：**`ErpManagedSaleOutPort / ErpStockRecordServiceImpl`；结合阶段报告中的实际场景与证据。

<a id="s03"></a>

## S03 发货商品、价格和税率从哪来？

**短答：**来自冻结销售单及ERP规则，客户端只指定执行身份和数量等允许字段。

**展开：**订单项映射保留价格来源；不让客户端任意传商品/金额成为真实ERP单据，避免执行事实与商业依据分离。

**继续追问：**伪造另一预占ID怎么办？

**易错：**只校验数量正数而不校验归属。

**定位：**`ERP createAndApprove实现`；结合阶段报告中的实际场景与证据。

<a id="s04"></a>

## S04 ERP审核返回成功后履约失败怎么办？

**短答：**因为MANDATORY加入同库事务，整体回滚包括ERP和履约全部事实。

**展开：**历史在ERP内部库存批次后和审核返回后都注入异常；Redis单号可能留空号，不承诺跨组件事务。

**继续追问：**只在ERP调用前抛错够吗？

**易错：**只看履约无发货行就断言ERP已回滚。

**定位：**`M3-erp-approval-failure.json / m3_acceptance.py`；结合阶段报告中的实际场景与证据。

<a id="s05"></a>

## S05 取消为什么先处理open？

**短答：**open没有占仓，先取消它无需释放库存；余量再从预占按ID释放。

**展开：**open2/reserved5取消4，R只减2，cancelled增4。原ordered保持，shipped不变；保存取消事实和原因。

**继续追问：**取消与发货竞争时怎么决定？

**易错：**把取消总量全部从R减。

**定位：**`FulExecutionService.cancel`；结合阶段报告中的实际场景与证据。

<a id="s06"></a>

## S06 为什么托管订单手工出库仍禁用？

**短答：**否则可以绕开预占消费、命令幂等和发货事实，仅ERP扣H会造成执行汇总不一致。

**展开：**受控Java内部端口是明确业务入口，不向HTTP开放managed/internal旁路字段；UI禁选是辅助，后端仍拒绝。

**继续追问：**出库反审核是否可直接调用？

**易错：**放一个全局线程变量让所有入口通行。

**定位：**`ErpManagedOrderGuard / 内部Port`；结合阶段报告中的实际场景与证据。

<a id="s07"></a>

## S07 物流验签签的具体内容是什么？

**短答：**timestamp换行eventId换行原始body字节，HMAC-SHA256，签名十六进制。

**展开：**限制五分钟窗口和头格式/body大小，配置integrationId映射provider/tenant/secret；签名有效仍需业务去重。

**继续追问：**重新序列化JSON再验签会怎样？

**易错：**只对shipmentNo或JSON对象字符串签名。

**定位：**`LogisticsSignature.sign/verify`；结合阶段报告中的实际场景与证据。

<a id="s08"></a>

## S08 为什么回调租户不能从body取？

**短答：**外部可伪造tenant字段，服务端应通过已配置集成确定租户并验证有效性。

**展开：**验签后设置tenant并恢复ignore=false，finally还原原上下文，避免线程复用串租户。当前仍未测试跨机时钟偏差。

**继续追问：**@PermitAll是否等于无需认证？

**易错：**相信客户端tenantId。

**定位：**`FulLogisticsCallbackController.receive`；结合阶段报告中的实际场景与证据。

<a id="s09"></a>

## S09 重复、冲突、乱序各如何处理？

**短答：**相同eventId同内容重放；同ID异内容记录冲突；签收后运输中只记录不回退。

**展开：**去重范围tenant/provider/eventId，业务hash不含易变签名头；回调只锁事件/发货，不写库存。

**继续追问：**重试换timestamp会被误认为新事件吗？

**易错：**把签名认证等同业务幂等。

**定位：**`FulLogisticsService.receive`；结合阶段报告中的实际场景与证据。

<a id="s10"></a>

## S10 冲突为什么不在事务里立刻抛错？

**短答：**需要先提交conflict_count等诊断，再在Controller返回业务错误，否则诊断随事务回滚。

**展开：**Service返回CONFLICT，代理事务完成，Controller映射CALLBACK_CONFLICT；这不是忽略错误，而是区分诊断保存与响应语义。

**继续追问：**未知发货会创建孤立回调行吗？

**易错：**抛错回滚后仍声称记录已保存。

**定位：**`FulLogisticsService / CallbackController`；结合阶段报告中的实际场景与证据。
