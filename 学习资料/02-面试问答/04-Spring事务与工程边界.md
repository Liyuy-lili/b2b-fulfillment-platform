## T01 事务在这里保证什么？

**短答：**一次命令内订单、预占、ERP单据/库存/流水和命令响应共同提交或回滚。

**展开：**不保证不同业务请求天然互斥，也不回滚Redis和外部HTTP。必须明确同数据源、代理和调用链。

**继续追问：**ERP成功后履约抛错会怎样？

**易错：**一句ACID代替具体表和边界。

**定位：**`FulExecutionService.ship`；结合本章阶段证据解释实际验证范围。

## T02 @Transactional何时可能不生效？

**短答：**没经过代理、对象自行new、同类自调用期望新事务、换线程或事务管理器不匹配等都需审查。

**展开：**本项目Controller经注入Service代理调用。已有外层事务中的自调用仍执行在外层，不能把所有自调用都说成完全无事务。

**继续追问：**createStockRecords内部自调用呢？

**易错：**把注解存在视为运行证据。

**定位：**`ErpStockRecordServiceImpl`；结合本章阶段证据解释实际验证范围。

<a id="t03"></a>

## T03 MANDATORY和REQUIRED在这里有什么区别？

**短答：**REQUIRED可加入或新建，MANDATORY要求已有事务；受控ERP端口不允许脱离履约事务独立运行。

**展开：**Port接口声明能力，实际ERP服务实现上配置传播；内部审核继承同库边界。

**继续追问：**无事务直接调用端口会怎样？

**易错：**只看接口名认为自动加入事务。

**定位：**`ErpSaleOutServiceImpl / ErpSaleReturnServiceImpl`；结合本章阶段证据解释实际验证范围。

<a id="t04"></a>

## T04 为什么不能用REQUIRES_NEW审核ERP？

**短答：**它可能让ERP先独立提交，之后履约失败无法共同回滚，留下真实出库却没有发货事实。

**展开：**当前业务需要核心强一致，外围通知后续异步；不能为了避免锁异常而拆开原子边界。

**继续追问：**外层回滚能撤销内层提交吗？

**易错：**把独立事务当万能容错。

**定位：**`ADR-012 / ADR-014`；结合本章阶段证据解释实际验证范围。

<a id="t05"></a>

## T05 为什么rollbackFor=Exception？

**短答：**核心方法显式要求检查异常也回滚，避免部分异常路径被默认规则忽略。

**展开：**实际还取决于异常是否传播到事务代理；catch后吞掉可能改变语义。锁异常要离开事务后再试。

**继续追问：**吞掉异常再返回成功会怎样？

**易错：**所有异常都不区分直接重试。

**定位：**`FulAllocationService / FulReturnService`；结合本章阶段证据解释实际验证范围。

<a id="t06"></a>

## T06 事务内为什么避免物流HTTP？

**短答：**远程响应不可和本地MySQL共同回滚，耗时还延长库存锁；当前签名模拟在独立链路。

**展开：**主事实本地提交，M5已在同事务写Outbox并异步发布/消费；库存不移交消费者。

**继续追问：**提交后通知失败怎么办？

**易错：**把本地读模型可靠处理外推第三方副作用必达。

**定位：**`FulLogisticsSimulatorController / FulOutboxService`；结合本章阶段证据解释实际验证范围。

<a id="t07"></a>

## T07 AOP重试如何包在事务外？

**短答：**ERP重试切面@Order(-100)包裹事务拦截器，新命令Controller先Retry.run再进Service代理。

**展开：**异常离开原事务并回滚后下一次重新进入；若已处于活动事务，交给最外层重试而不嵌套独立提交。

**继续追问：**顺序反过来有什么问题？

**易错：**在rollback-only事务里连续试三次。

**定位：**`ErpTransactionRetryAspect / DatabaseCommandRetry`；结合本章阶段证据解释实际验证范围。

<a id="t08"></a>

## T08 为什么要检查实际连接隔离和锁等待？

**短答：**配置文件可能未作用到真实数据源，启动时读取业务连接才能发现RC或timeout没有生效。

**展开：**锁测试同时观察真实参数与重试日志；Flyway用独立短连接处理结构，不能用它的连接冒充业务连接。

**继续追问：**只看application.yaml够吗？

**易错：**把声明值当已验证运行值。

**定位：**`FulfillmentFlywayConfiguration`；结合本章阶段证据解释实际验证范围。

<a id="t09"></a>

## T09 模块间接口为什么放在ERP？

**短答：**ERP需要声明托管策略而不依赖履约实现，履约依赖ERP并提供策略Bean，避免Maven循环。

**展开：**出入库Port也明确ERP业务能力；业务规则集中履约，ERP仍拥有原有实物库存路径。

**继续追问：**接口和实现如何被Spring发现？

**易错：**ERP直接import履约Service形成反依赖。

**定位：**`ErpManagedOrderPolicy / FulfillmentManagedOrderPolicy`；结合本章阶段证据解释实际验证范围。

<a id="t10"></a>

## T10 为什么不直接把DO当所有接口输入？

**短答：**持久化对象包含tenant、审计、ERP映射等服务端字段，直接绑定易扩大可写范围。

**展开：**Contracts限定客户端能提交的字段，Service从快照和原发货生成商业数据。Bean Validation只做格式，跨表规则仍需事务。

**继续追问：**前端传价格和原仓是否可信？

**易错：**认为前端表单没展示就无法伪造。

**定位：**`OrderContracts / ReturnContracts`；结合本章阶段证据解释实际验证范围。
