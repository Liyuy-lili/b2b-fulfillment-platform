# 测试证据与排障

[最终产物30场景回归](../10-验收证据/M7.2-验收报告.md)用于当前证据，原阶段链接用于解释历史设计。

先读 [配套学习](../01-系统学习教程/14-测试方法与证据阅读.md)，核对 [状态或历史证据](../10-验收证据/M4.2-验收报告.md)。F组已升级为完成能力与扩展边界；C组是学习现场推演，本轮没有新跑业务测试。

<a id="v01"></a>

## V01 怎样测试库存并发正确性？

**短答：**固定真实MySQL数据，两个JVM并发争有限库存，检查响应及事后库存、逐项事实与流水。

**展开：**M2历史H10/八单各3，三单成功R9；不要只检查接口都没500，也不把这叫压测。

**继续追问：**怎样确保请求确实交错？

**易错：**只开线程、不检查最后业务事实。

**定位：**`m2_acceptance.py / M2-two-instance.json`；见本章学习和证据链接。

<a id="v02"></a>

## V02 为什么不能只用H2做并发验证？

**短答：**真实MySQL的锁、隔离、约束和SQL行为才是目标，需要实际数据库集成。

**展开：**纯算法仍适合JUnit快速验证；mock不能证明FOR UPDATE和Spring跨模块回滚。测试层次互补，不要求每个规则都启动完整应用。

**继续追问：**哪些规则适合纯单测？

**易错：**单测绿就宣布数据库竞争通过。

**定位：**`AllocationPlannerTest / tests集成脚本`；见本章学习和证据链接。

<a id="v03"></a>

## V03 故障点怎么选？

**短答：**选择可能已写核心事实但还未完成事务的边界，例如ERP库存批次后、审核返回后。

**展开：**对比全链路快照而非单一库存，确认命令也回滚、原key恢复成功，故障只在专用profile。

**继续追问：**在调用前抛错为什么证据较弱？

**易错：**用HTTP公开故障开关。

**定位：**`M3与M4.2核心验收`；见本章学习和证据链接。

<a id="v04"></a>

## V04 怎样证明整事务重试真实发生？

**短答：**用外部事务占行超过实际锁等待，检查日志next attempt及最终仅一个效果。

**展开：**等锁后成功也可能从未超时，所以还检查真实RC/timeout、错误与重试记录，不靠耗时猜。

**继续追问：**最大次数用完返回什么？

**易错：**请求慢一点就算已验证重试。

**定位：**`m2_legacy_inventory.py / DatabaseCommandRetry`；见本章学习和证据链接。

<a id="v05"></a>

## V05 为什么要干净库和已有库两种验证？

**短答：**干净库验证可重建，升级验证已有事实保持且新迁移正确接入。

**展开：**M4.2新库0—4、主库V3→V4、负约束探针分别有记录。升级脚本是一次性前提，当前V8不应重复执行旧升级脚本。

**继续追问：**结构校验覆盖全部生产历史吗？

**易错：**只在开发库手工改表后宣称部署可复现。

**定位：**`M4.2-upgrade.json / constraints.json`；见本章学习和证据链接。

<a id="v06"></a>

## V06 正常重启验证什么？

**短答：**正常停止/启动依赖和应用后，事实快照保持，原key重放不产生重复业务。

**展开：**不等于突然断电、磁盘故障或全部崩溃窗口；RedisAOF everysec有自己的持久化边界。当前未做灾备全验证。

**继续追问：**需要额外测试哪类故障？

**易错：**说任何宕机零丢失。

**定位：**`M4.2-restart.json / replay-after-restart`；见本章学习和证据链接。

<a id="v07"></a>

## V07 不同构建的结果怎样组合才诚实？

**短答：**保留每阶段产物摘要，说明核心先测写流程，最终新增只读查询后再做API/ERP回归。

**展开：**M7用最终同jar重跑关键场景，M4.2-final-api仍解释当时两个构建；本轮资料检查不算应用重跑。

**继续追问：**源文件改后旧证据还能说明什么？

**易错：**只要报告存在就忽略产物版本。

**定位：**`M4.2-final-api.json / changes.json`；见本章学习和证据链接。

<a id="v08"></a>

## V08 端口被占和页面连不上怎样查？

**短答：**先监听/PID/命令行/日志，辨别项目端口与系统服务，再检查启动是否完成。

**展开：**本项目33306与系统3306不同，不能批量杀所有Java/MySQL。历史PID不可当当前状态，启动失败不立刻清库。

**继续追问：**浏览器等待超时要重复提交吗？

**易错：**不核对结果就连续点击写命令。

**定位：**`scripts/Start-Local.ps1 / .local日志`；见本章学习和证据链接。

<a id="v09"></a>

## V09 生成单号失败怎么处理？

**短答：**查Redis持久化与SQL已存在单号，恢复正确序列；项目有只提升当天计数上界的维护脚本。

**展开：**执行前停ERP写入，保留数据库与Redis数据目录，不flush缓存碰运气。序列回滚空号与重复号是不同问题。

**继续追问：**为什么Redis不是可随便丢的缓存？

**易错：**删Redis数据解决编号冲突。

**定位：**`repair_erp_sequences.py / 根README`；见本章学习和证据链接。

<a id="v10"></a>

## V10 怎样准确讲M7性能结果？

**短答：**引用M7本机合成查询1152样本、V8索引交替对比、库存512请求和两次导出观测，说明环境和局限。

**展开：**并发4查询P95从158.58到74.43ms、并发8从147.57到76.64ms，环境/负载见M7.3；不把单次导出当统计提速，不外推生产。

**继续追问：**如何设计第一轮压测？

**易错：**把双JVM正确性当高吞吐证据。

**定位：**`M7.3-query.json / M7.3-summary.json / 学习资料29`；见本章学习和证据链接。
